## 📚 TROUBLESHOOTING GUIDE

### Problem 1: npm install masih gagal

**Symptoms:** Timeout, network errors, partial install

**Solutions:**
```powershell
# Option 1: Increase timeout
npm install --network-timeout=300000

# Option 2: Use different registry
npm install --registry=https://registry.npmmirror.com

# Option 3: Legacy peer deps
npm install --legacy-peer-deps

# Option 4: Force clean install
Remove-Item -Recurse -Force node_modules
Remove-Item package-lock.json
npm cache clean --force
npm install
```

### Problem 2: Antivirus blocking npm

**Symptoms:** Files disappear after install, random ENOENT

**Solutions:**
1. Add exclusion: `node_modules/`, `npm-cache/`
2. Temporarily disable real-time scanning
3. Use `npm ci` instead of `npm install` (faster, less I/O)

### Problem 3: Disk space full

**Check:**
```powershell
# Check free space
Get-PSDrive C | Select-Object Used,Free

# Check node_modules size
(Get-ChildItem node_modules -Recurse | Measure-Object -Property Length -Sum).Sum / 1MB
```

**Cleanup:**
```powershell
# Clear npm cache (can save GBs)
npm cache clean --force

# Clear global packages cache
npm cache verify
```

### Problem 4: Build still fails after reinstall

**Advanced debugging:**
```powershell
# Check Node version
node --version  # Should be >= 20

# Check npm version
npm --version   # Should be >= 10

# Check package.json syntax
Get-Content package.json | ConvertFrom-Json

# Verbose build for detailed errors
npm run build --verbose
```

## 📖 EDUCATIONAL NOTES

### Why node_modules Corrupts?

**Common Scenarios:**

1. **Interrupt During Install:**
   ```
   npm install
   (User presses Ctrl+C)
   → Partial files written
   → Next run fails
   ```

2. **Concurrent npm Commands:**
   ```
   Terminal 1: npm install
   Terminal 2: npm install (same time)
   → File locks conflict
   → Corruption
   ```

3. **Antivirus Scanning:**
   ```
   npm writes file.js
   Antivirus scans → blocks temporarily
   npm thinks write failed
   → Partial file
   ```

### Why We Use package-lock.json?

**Without lock file:**
```
Day 1: npm install
  → vite@7.3.2 installed

Day 7: npm install (on CI/CD)
  → vite@7.3.3 released
  → CI gets different version
  → "Works on my machine" bug
```

**With lock file:**
```
Day 1: npm install
  → vite@7.3.2
  → package-lock.json records exact version

Day 7: npm install (anywhere)
  → package-lock.json enforces 7.3.2
  → Consistent across all environments
```

## 🎓 BEST PRACTICES

### 1. Always Use npm ci in CI/CD

```yaml
# ✅ GOOD
- run: npm ci

# ❌ BAD
- run: npm install
```

**Why?**
- `npm ci` deletes node_modules first (clean slate)
- Respects package-lock.json exactly
- Faster (no dependency resolution)
- Fails if package.json and lock are out of sync

### 2. Lock File Strategy

```powershell
# Development
npm install package-name
git add package.json package-lock.json
git commit -m "feat: add package-name"

# Production deployment
npm ci  # Never npm install
```

### 3. Regular Maintenance

```powershell
# Every sprint (2 weeks)
npm outdated
npm update  # Minor & patch updates

# Every quarter
npm install package@latest  # Major updates
npm test
```
