# 📝 GITIGNORE CONFIGURATION GUIDE

## Apa yang Berubah?

`.gitignore` telah diperbaiki dari versi minimal (2 baris) menjadi comprehensive configuration untuk project Vite + React + TypeScript + PWA.

## 🔍 Kategori File yang Di-ignore

### 1. **Dependencies** (CRITICAL)
```
node_modules/          # 2,634 files yang tidak perlu di-track
.yarn/cache/           # Yarn v2+ cache
```
**Kenapa?** Package manager akan re-install dari `package.json` & lock file.

### 2. **Build Output** (CRITICAL)
```
dist/                  # Output dari npm run build
dist-ssr/              # Server-side rendering output (jika ada)
build/                 # Alternative build folder
```
**Kenapa?** Build artifacts di-generate ulang setiap deploy, tidak perlu version control.

### 3. **Cache Directories**
```
.vite/                 # Vite cache untuk HMR
.cache/                # Generic cache
```
**Kenapa?** Cache bersifat lokal per developer, tidak portable.

### 4. **Environment Variables** (SECURITY)
```
.env
.env.local
.env.*.local
```
**Kenapa?** File ini bisa berisi API keys, database credentials, secrets.

### 5. **Editor-Specific**
```
.vscode/*              # VS Code settings
!.vscode/extensions.json  # KECUALI recommended extensions
.idea/                 # JetBrains IDEs
.DS_Store              # macOS Finder
```
**Kenapa?** Setiap developer punya preference editor berbeda.

### 6. **Testing Artifacts**
```
coverage/              # Coverage reports
screenshots/           # Playwright screenshots
test-results/          # Test output
```
**Kenapa?** Test results bersifat lokal, CI/CD akan generate sendiri.

### 7. **PWA Service Worker** (Development)
```
dev-dist/              # Vite PWA dev cache
sw.js                  # Generated service worker
workbox-*.js           # Workbox runtime
```
**Kenapa?** Generated files, akan di-bundle ulang untuk production.

### 8. **Logs**
```
*.log
npm-debug.log*
yarn-error.log*
```
**Kenapa?** Debug logs bersifat temporary dan personal.

## ✅ File yang TETAP Di-track

File-file ini **tidak** di-ignore karena penting untuk repo:

```
✅ package.json          # Dependency list
✅ package-lock.json     # Lock file untuk npm (keep!)
✅ vite.config.ts        # Build configuration
✅ tsconfig.json         # TypeScript config
✅ tailwind.config.ts    # Tailwind config
✅ netlify.toml          # Deploy config
✅ public/               # Static assets (manifest, icons)
✅ src/                  # Source code
✅ content/              # Curriculum markdown
✅ ANALISIS*.md          # Documentation
✅ SPESIFIKASI*.md       # Specs
✅ README.md             # Project readme
```

## 🚨 CRITICAL: Package Lock Files

**Pilihan Strategis:** Project ini menggunakan **npm**, jadi:

```gitignore
# KEEP (don't ignore):
package-lock.json

# IGNORE (uncomment jika switch):
# yarn.lock
# pnpm-lock.yaml
```

**Kenapa lock file penting?**
- Ensure reproducible builds
- Prevent "works on my machine" issues
- Lock specific versions (termasuk transitive dependencies)

## 🔧 Cara Membersihkan Files yang Sudah Ter-track

Jika `node_modules/` atau `dist/` sudah ter-track sebelumnya:

```bash
# Remove from Git index (keep local files)
git rm -r --cached node_modules
git rm -r --cached dist

# Commit the removal
git add .gitignore
git commit -m "chore: fix .gitignore - untrack node_modules and dist"

# Verify
git status  # Should show "clean working tree"
```

## 🎯 Best Practices

### 1. **Never commit secrets**
```bash
# Before first commit, check:
git diff --cached | grep -i "api_key\|password\|secret\|token"
```

### 2. **Use environment variables**
```typescript
// ❌ BAD
const API_KEY = "sk-1234567890abcdef";

// ✅ GOOD
const API_KEY = import.meta.env.VITE_API_KEY;
```

### 3. **Check before push**
```bash
# See what will be pushed
git diff origin/main..HEAD --name-only

# Should NOT include:
# - node_modules/
# - dist/
# - .env
# - *.log
```

## 🔍 Debugging Gitignore

### Check if file is ignored:
```bash
git check-ignore -v node_modules/
# Output: .gitignore:6:node_modules/    node_modules/
```

### See all ignored files:
```bash
git status --ignored
```

### Force add ignored file (jika perlu):
```bash
git add -f path/to/file.txt
```

## 🚀 Quick Commands

```bash
# Clean all ignored files (DESTRUCTIVE!)
git clean -fdX

# Dry run first (safe):
git clean -ndX

# Remove specific folder:
git clean -fdX node_modules/

# Update .gitignore and refresh index:
git rm -r --cached .
git add .
git commit -m "chore: apply new .gitignore"
```

## ⚠️ Common Mistakes

### ❌ Mistake 1: Ignore lock files
```gitignore
package-lock.json  # DON'T DO THIS!
```
**Impact:** Different developers get different dependency versions → bugs.

### ❌ Mistake 2: Ignore .vscode/ completely
```gitignore
.vscode/  # TOO BROAD!
```
**Better:**
```gitignore
.vscode/*
!.vscode/extensions.json
!.vscode/settings.json
```

### ❌ Mistake 3: Commit .env
```bash
git add .env  # NEVER!
```
**Recovery:**
```bash
git rm --cached .env
git commit --amend
# If pushed: git push --force (coordinate with team!)
```

## 🎓 Educational Note

Untuk siswa/mahasiswa yang belajar Git:

**Why we ignore node_modules:**
1. **Size**: 100MB+ untuk project medium
2. **Redundancy**: Semua info ada di package.json
3. **Platform-specific**: Native modules beda per OS
4. **Performance**: Git slow untuk track 1000+ files

**How npm install works:**
```
package.json (what) + package-lock.json (exact versions)
         ↓
    npm install
         ↓
  node_modules/ (restored)
```
